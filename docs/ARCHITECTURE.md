# Архитектура

Один Java-процесс отдаёт REST API и собранный фронт. Проекты и версии находятся в памяти; перезапуск сервера очищает их.

`parse` получает AST через JavaParser. `graph` строит карту и чертёж метода; `ExprTreeBuilder` раскрывает выражения. Стабильные идентификаторы операторов не включают номера строк. `project` хранит версии и последнюю разобранную схему, `commands` проверяет правку выбранного диапазона и неизменность остальных токенов, затем выполняет javac и обновляет код со схемой.

`diag` читает AST и создаёт находки с условиями применения. Изменение дефекта помечается `BUGFIX`, эквивалентная оптимизация — `REFACTOR`. Сами находки не доказывают сохранение поведения.

`gate` компилирует исходную версию и кандидат. `inputs` создаёт входы по чтениям `Scanner`. `runner` выполняет байткод в рабочих JVM с одинаковыми JDK, локалью en_US и UTF-8. Оригинал повторяется для выявления нестабильного вывода. `oracle` сравнивает результаты по правилам [ORACLE.md](ORACLE.md).

Явные операции чтения или печати стека распознаются по AST и включают прямой запуск настоящего `java main`. Если режим нужен одной версии, обе сравниваются в этом режиме. `PlainJavaRunner` использует отдельные процессы, ограничивает захваченный вывод и очищает собственные временные каталоги, не следуя по ссылкам. Сам stderr не переписывается; дополнительные сведения о необработанном исключении выделяются по заголовку JVM.

`instrument` работает с отдельными копиями обеих версий. Счётчик перед оператором отвечает, на скольких разных сравнённых входах он выполнялся. Сводка покрытия не заменяет результаты чистых прогонов. Ошибка замера, изменения объявлений и слишком редкое выполнение приводят к неполной проверке. Для программ, наблюдающих стек, покрытие реальной правки пока не измеряется: вставка счётчиков могла бы повлиять на наблюдаемый результат.

Фронт хранит исходный эталон отдельно от текущего текста и явно передаёт его в `/gate`. Дерево выражений получает с сервера; клик выбирает оператор для правки и точный включительный диапазон выражения для Monaco. Моки включаются только явным флагом разработки.

Изолирующей песочницы нет. Доступ загруженной программы к файлам, сети и другим возможностям JVM не ограничивается.
