# Контракт API: Бэк ↔ Фронт

> **Правило:** меняем только вдвоём. Изменили здесь → поправили `backend/` и `frontend/src/api/types.ts` → перевыгрузили фикстуры.
> Все ответы — JSON в UTF-8. Ошибка — HTTP-статус + `{"error": "текст по-русски"}`.
> Разработка: фронт на `:5173` проксирует `/api` на бэк `:8080` (`vite.config.ts`). В сборке всё на одном порту `:8080`.

## Общие типы

### Узел схемы `GraphNode`
```json
{
  "id": "M:MiniLang.Token#<init>(Tok,String,Object,int)",
  "kind": "method",
  "label": "new Token(Tok, String, Object, int)",
  "code": null,
  "lines": [44, 46],
  "parent": "C:MiniLang.Token",
  "branch": null,
  "badges": []
}
```
| Поле | Значение |
|---|---|
| `id` | Стабильный: не зависит от позиции в файле. Уровень 0: `C:Класс`, `F:Класс.поле`, `M:Класс#метод(Тип,Тип)`; конструктор — `#<init>(…)`, блок `static {}` — `#<clinit>()`; повтор — суффикс `~2` |
| `kind` | `class` `field` `method` — уровень 0; `stmt` `if` `loop` `switch` `try` `return` `throw` `break` `continue` `raw` — уровень 1 |
| `label` | Что написать на узле |
| `code` | Исходный текст фрагмента (у полей и операторов), иначе `null` |
| `lines` | `[первая, последняя]` строка исходника, с 1 |
| `parent` | id родителя: для метода — класс, для вложенного класса — внешний, для оператора — контейнер |
| `branch` | Только уровень 1: `then` `else` `body` `case:N` `catch:N` `finally` |
| `badges` | Сработавшие правила находок: `["R1"]` |
| `complexity` | Оценка сложности по структуре кода — у методов на карте и у циклов на чертеже, иначе поля нет: `{ "big": "O(n²)", "level": "high", "why": "Оценка сверху по структуре кода…: цикл (стр. 14) → цикл (стр. 15)…" }`. `level`: `low` (O(1), O(log n)), `linear` (O(n), O(n log n)), `high` (n² и выше), `unknown` (`big` = «рекурсия»). Это оценка сверху, а не замер; замер — `POST /profile` |

### Дерево выражения `ExprNode` (чертёж метода, «подробная схема») — сб 24.10, 16:00
Заказчик: «схема нужна подробная»; техдокумент: «конструкции языка реализуются как узлы графа». Поэтому у каждого узла чертежа, где есть выражение, появляется поле `expr` — дерево этого выражения. На карте (уровень 0) `expr` нет.

Какое выражение лежит в `expr`:

| Узел | `expr` |
|---|---|
| `stmt`: выражение-оператор | само выражение (`total++`, `list.add(x)`, `a = b + c`) |
| `stmt`: объявление переменной | `declare` с детьми по переменным; у каждой — инициализатор |
| `if`, `while`, `do` | условие |
| `for` | `forHeader`, дети с ролями `инициализация` / `условие` / `шаг` |
| for-each | `forEachHeader`, дети `элемент` (`declare`) и `коллекция` |
| `switch` | селектор |
| `return`, `throw` | значение (у `return;` — `null`) |
| `try` с ресурсами | `resources` |
| остальное (`break`, `continue`, `raw`) | `null` |

```json
{ "id": "S:…#3f2a/e", "kind": "call", "label": "Objects.equals", "code": "Objects.equals(x, y)",
  "range": [16, 17, 16, 36], "role": null,
  "children": [
    { "id": "…/e/0", "kind": "name", "label": "x", "code": "x", "range": [16, 32, 16, 32], "role": "арг 1", "children": [] },
    { "id": "…/e/1", "kind": "name", "label": "y", "code": "y", "range": [16, 35, 16, 35], "role": "арг 2", "children": [] } ] }
```

| Поле | Значение |
|---|---|
| `id` | id узла-оператора + `/e` + путь индексов детей (`/e/0/1`). Стабилен, пока не меняется сам оператор |
| `kind` | см. таблицу ниже |
| `label` | коротко, что показать на узле: имя метода, знак операции, тип, значение литерала |
| `code` | исходный текст выражения (до 200 символов, дальше `…`) |
| `range` | `[строка, колонка, строка конца, колонка конца]`, с 1 включительно — для подсветки в редакторе |
| `role` | роль в родителе по-русски: `объект`, `арг N`, `условие`, `да`, `нет`, `слева`, `справа`, `значение`, `индекс`, `тело`, `инициализация`, `шаг`, `элемент`, `коллекция`; у корня — `null` |
| `children` | вложенные выражения по порядку; у листьев — `[]` |

`kind`:
- `call` — вызов метода; `label` = `имя` или `объект.имя` для статических/коротких; дети `объект?`, `арг N`;
- `new` — создание объекта или массива; `label` = `new Тип`;
- `binary` — бинарная операция; `label` = знак: `+ - * / % && || & | ^ << >> >>> == != < > <= >=`;
- `concat` — `+`, где хотя бы один операнд — строковый литерал или другой `concat`. Типы не вычисляем — это эвристика, так и пишем;
- `unary` — `! - + ~ ++x x++ --x x--`; `label` = знак;
- `assign` — `= += -= …`; дети `цель`, `значение`;
- `ternary` — дети `условие`, `да`, `нет`;
- `instanceof` — `label` = `instanceof Тип` (с переменной шаблона, если есть);
- `cast` — `label` = `(Тип)`;
- `lambda` — `label` = `(параметры) ->`; ребёнок `тело`: выражение или `block` с `label` «{ N операторов }»;
- `methodRef` — `Класс::метод`;
- `literal` — число, строка, `char`, `true/false`, `null`; `label` = значение, строка обрезается до 30 символов;
- `name` — переменная или поле;
- `field` — `объект.поле`; ребёнок `объект`;
- `index` — `a[i]`; дети `массив`, `индекс`;
- `arrayInit` — `{1, 2, 3}`;
- `switchExpr` — switch-выражение; дети `селектор` и `case N`;
- `declare`, `forHeader`, `forEachHeader`, `resources`, `block` — служебные узлы из таблицы выше;
- `other` — всё остальное, `label` = текст.

Глубина не ограничена, но у узла больше 12 детей — первые 12 и узел `other` с текстом «ещё N». Правка остаётся на уровне оператора (`editStatement`): клик по узлу выражения выбирает его оператор и подсвечивает `range` в коде.

### Ребро `GraphEdge`
```json
{ "id": "M:MiniLang.Lexer#scan()->M:MiniLang.Lexer#atEnd()",
  "from": "M:MiniLang.Lexer#scan()", "to": "M:MiniLang.Lexer#atEnd()",
  "kind": "call", "label": "вызов" }
```
`kind`: `call` — «вызывает» (уровень 0), `exec` — порядок выполнения (уровень 1).
`label` у `call`: `вызов` — цель одна и найдена точно; `вызов?` — предположение: вызов на переменной (тип неизвестен) или несколько перегрузок с тем же числом аргументов. Рисовать `вызов?` пунктиром.
Не на карте: вызовы методов JDK, вызовы из локальных и анонимных классов и из инициализаторов полей. Подробно — `docs/аудит_v2/РАЗБОР.md`.

## ✅ POST `/api/projects` — загрузить монолит
Запрос: `{ "fileName": "MiniLang.java", "source": "…весь текст…" }`
Ответ `201`:
```json
{ "id": "5b735a3b", "version": 1, "fileName": "MiniLang.java", "source": "…",
  "errors": [], "compileErrors": [],
  "map": { "nodes": [ GraphNode… ], "edges": [ GraphEdge… ] } }
```
Ошибки: `400` — пустой код или больше 1 000 000 символов.
Если код не разбирается: `201`, `errors` не пуст, `map` пустой.
`compileErrors` — ошибки javac: `[{"line": 4, "column": 13, "text": "…"}]`.
Синтаксически корректный код может не компилироваться; его схема при этом доступна.

## ✅ GET `/api/projects/{id}`
Ответ `200` — та же форма. `404` — нет такого проекта (сервер перезапускали — загрузить заново).

## ✅ PUT `/api/projects/{id}/source` — правка кода в редакторе
Запрос: `{ "source": "…", "baseVersion": 1 }` — `baseVersion` = версия, к которой сделана правка.
Ответ `200` — та же форма, `version` +1. Если новый код не разбирается: `errors` не пуст, а `map` **остаётся от последней рабочей версии** — фронт показывает баннер «код не разбирается: строка N» и старую схему.
`409` — версия устарела (кто-то правил параллельно): перезапросить проект.

## ✅ GET `/api/projects/{id}/methods/{methodId}` — чертёж метода
`methodId` — id метода из карты, URL-кодированный (`encodeURIComponent`).
Ответ: `{ "nodes": [GraphNode…], "edges": [GraphEdge…] }` — операторы метода, `edges.kind = "exec"`.
Контейнеры (`if`, `loop`, `switch`, `try`) — узлы-родители; операторы внутри них имеют `parent` = id контейнера и `branch`.
id операторов: id родителя + хэш нормализованного текста + номер повтора (без позиций).

## ✅ POST `/api/projects/{id}/commands` — правка узла
Запрос: `{ "type": "editStatement", "nodeId": "…", "text": "total += price * qty;", "baseVersion": 3 }`
Ответ `200`: `{ "ok": true, "version": 4, "source": "…", "map": Graph, "idMap": { "старый id": "новый id" }, "compileErrors": [] }`
Не компилируется: `{ "ok": false, "compileErrors": [{ "line": 12, "column": 5, "text": "…по-русски…" }] }` — версия не меняется.

## ✅ GET `/api/projects/{id}/findings` — находки
Настоящий ответ на `MatchDemo.java` (вс 25.10; `source` заплатки сокращён):
```json
[{ "id": "R1-1", "rule": "R1", "category": "INEFFICIENCY",
   "methodId": "M:MatchDemo#countMatches(List<Integer>,List<Integer>)", "lines": [14, 20],
   "title": "Вложенный цикл",
   "why": "Для каждого элемента a просматривается весь список b: число сравнений растёт как n². …",
   "growthBefore": "n²", "growthAfter": "n",
   "conditions": ["Списки a и b не меняются внутри цикла", "У элементов согласованы equals и hashCode", "…"],
   "patches": [{ "id": "R1-1-index", "intent": "REFACTOR", "title": "Индекс частот вместо перебора",
                 "description": "Один проход по b строит таблицу «значение → сколько раз встретилось»…",
                 "source": "…полный текст файла с заплаткой…", "changedLines": [14, 23] }] }]
```
| Поле | Значение |
|---|---|
| `id` | правило + номер: `R1-1`; id заплатки — id находки + суффикс (`-index`, `-builder`, `-fix`, `-remove`) |
| `methodId` | id метода с карты, к которому относится находка |
| `growthBefore`, `growthAfter` | оценка роста по структуре; `null` у правил, которые сложность не оценивают |
| `patches[].source` | полный текст файла с заплаткой — его фронт отправляет в `POST /gate` |
| `patches[].changedLines` | `[первая, последняя]` строка новой версии, занятые заменой |

## ✅ POST `/api/projects/{id}/profile` — замер роста
Считает выполнения тел циклов (операции, а не время) в копии кода со счётчиками на входах n = 100, 200, 400, 800, 1600.
Запрос: `{ "findingId": "R1-1", "patchId": "R1-1-index" }`; `patchId` необязателен — тогда меряется только оригинал.
Настоящий ответ на MatchDemo (вс 25.10, `note` сокращён):
```json
{ "supported": true, "sizes": [100, 200, 400, 800, 1600],
  "before": { "counts": [10100, 40200, 160400, 640800, 2561600], "model": "n²", "slope": 2, "lines": [14, 20], "loops": 2 },
  "after":  { "counts": [200, 400, 800, 1600, 3200], "model": "n", "slope": 1, "lines": [14, 23], "loops": 2 },
  "factor": 800.5,
  "note": "Считали выполнения тел циклов (операции, а не время): до — в строках находки 14–20, после — в строках замены 14–23; …",
  "durationMs": 2279 }
```
| Поле | Значение |
|---|---|
| `before`, `after` | ряд одной версии: `counts` по размерам, `model` — 1, log n, n, n log n, n², n³; `slope` — наклон на лог-лог шкале; `lines` и `loops` — какие циклы считались |
| `after` | `null`, если заплатку не передали или её не измерить |
| `factor` | во сколько раз меньше выполнений у заплатки на наибольшем n; `null` — сравнивать нечего |
| `note` | по-русски: что и как измерено, что пропущено |

Если измерить нельзя — `{ "supported": false, "note": "…почему…" }` без чисел: программа не читает `System.in`, ввод не построчный или не из целых чисел, программа отвергла вход, читает или печатает стек, в строках находки нет циклов.
Ошибки: `404` — нет проекта, находки или заплатки; `400` — неверный JSON, нет `findingId` или код не разбирается.
Входы поддержаны такие: строки целых чисел, которые программа читает через `Scanner.nextLine` и `Integer`/`Long` `parse*`/`valueOf`.

## ✅ POST `/api/projects/{id}/run` — прогон
Запрос: `{ "input": "текст stdin" }` → `{ "stdout": "…", "stderr": "…", "exitCode": 0, "exception": null, "timedOut": false, "durationMs": 21, "outputUnknown": false, "outputTruncated": false }`.
`exitCode = null`, если код выхода неизвестен. `exception` — `{type, message}` либо `null`. Обычный прогон не возвращает тепловую карту или счётчики; `coverageHits` используется только для отдельной копии «замер» и отсутствует при `null`. Числа в JSON здесь описывают форму ответа, а фактические результаты приведены в SCOPE.md.

## ✅ POST `/api/projects/{id}/gate` → GET `/api/jobs/{jobId}` — проверка заплатки
Запрос: `{ "source": "…кандидат…", "intent": "REFACTOR", "originalSource": "…эталон…" }` → `{ "jobId": "j1" }`.
`originalSource` необязателен: без него эталон — текущая версия проекта. Для правок редактора фронт передаёт сохранённый эталон явно, чтобы не сравнивать новую версию с ней самой. Для проверки заплатки передаётся её полный `source` из находки; запрос только с `patchId` не реализован.
Опрашивать `GET /api/jobs/{jobId}` раз в 300 мс, пока `progress < 1`. Настоящий итог проверки заплатки R1 на MatchDemo (вс 25.10; `example`, `statements` и часть групп сокращены):
```json
{ "status": "MATCHED", "phase": "done", "progress": 1,
  "inputs": 41, "checked": 41, "matched": 41, "mismatches": 0, "nondeterministic": 0,
  "incompleteReason": null, "buildErrors": [],
  "smallestMismatch": null, "example": { … },
  "groups": [{ "name": "Значения null", "total": 6, "checked": 6, "matched": 6, "status": "MATCHED" }, …],
  "changedCovered": { "lines": 7, "covered": 7, "minHits": 30, "inputsReached": 40, "inputs": 41, "onOriginal": false, "statements": […] },
  "speedup": null, "durationMs": 7652 }
```
`durationMs` сильно зависит от загрузки машины: этот прогон шёл параллельно с полной сборкой проекта.
`status` во время проверки — `RUNNING`, `phase` — `compile`, `run`, `compare`, `done`. `smallestMismatch` и `example` — пары прогонов `{ input, group, original, candidate, differences }` в форме ответа `/run`. `speedup` всегда `null`: рост измеряет отдельный `POST /profile`.

| Статус | Цвет | Что показать |
|---|---|---|
| `MATCHED` | 🟢 | «Совпало на N входах», покрытие изменённых строк |
| `MISMATCH` | 🔴 | Самый маленький вход и два результата рядом, разница подсвечена |
| `INCOMPLETE` | 🟡 | `incompleteReason`: что не проверено (таймаут, строки не выполнялись) |
| `BUILD_ERROR` | 🔴 | Ошибки компилятора |
| `BEHAVIOR_CHANGE` | 🟡 | «Исправление дефекта меняет поведение» + таблица изменений; **никогда не зелёный** |

### Покрытие изменений `changedCovered`

Счётчики выполняются только на отдельной копии; сравнение поведения использует чистый код.
Измеряются операторы кандидата и удалённые/заменённые операторы эталона. Учитываются только входы, на которых чистые версии действительно сравнены и получены счётчики обеих сторон.

| Поле | Значение |
|---|---|
| `lines` | Число измеренных **операторов** обеих версий; имя сохранено для совместимости. Это не число уникальных строк |
| `covered` | Сколько операторов выполнилось хотя бы на одном учтённом входе |
| `minHits` | На скольких **разных входах** выполнился самый редкий оператор; итерации цикла не суммируются |
| `inputsReached`, `inputs` | Сколько учтённых входов дошло хотя бы до одного оператора и сколько входов учтено всего |
| `onOriginal` | Все измеренные операторы относятся только к эталону |
| `statements` | `[{line, inputs, onOriginal}]`; `line` относится к версии, указанной в `onOriginal` |

Для реальной правки сбой замера, неизмеримое объявление или `minHits < 3` запрещают `MATCHED`: результат `INCOMPLETE` с причиной. Поля, сигнатуры и другие объявления не измеряются, в том числе рядом с измеримой правкой. Отсутствие изменения AST, включая форматирование и комментарии, допускает `changedCovered = null`. Значимые пробелы текстового блока не считаются отсутствием изменения.
Программы с явным чтением или печатью стека запускаются настоящей отдельной JVM. Если режим нужен одной стороне, обе сравниваются так же. Покрытие реальной правки в этом режиме пока не измеряется, поэтому без расхождения результат будет `INCOMPLETE`; текст stdout/stderr не подчищается.

### Категории и ограничения находок

`Finding.category`: `INEFFICIENCY`, `DEFECT` или `DEAD_CODE`. `growthBefore` и `growthAfter` могут быть `null`; интерфейс тогда не показывает оценку роста.
R2/R4/R5/R7/R8 содержат условия и предупреждают о потенциальном дефекте: совпадение шаблона не доказывает ошибочность замысла автора. Исправления дефектов помечены `BUGFIX`, а не `REFACTOR`.
R3 ограничен простым классом без наследования, вложенных типов, аннотаций и обнаруженной рефлексии; перегрузки, ссылки на методы и неизвестные вызовы сохраняются. Удаление недостижимой группы сохраняет переводы строк. Статическое основание R3 не отменяет динамическую проверку покрытия и не обещает зелёный результат.

## ✅ GET `/api/projects/{id}/export/junit?jobId=…` — экспорт тестов
Экспорт делается по завершённой проверке: эталон — выводы оригинала на её входах.
Ответ — ZIP (`Content-Disposition: attachment`), например `MatchDemo-tests.zip`: мини-проект Maven с исходником и тестом `src/test/java/MatchDemoCharacterizationTest.java`, по одному тесту «вход → ожидаемые stdout, stderr и код выхода» на каждый сравнённый вход. Входы со случайным, неизвестным или слишком большим выводом эталона пропускаются (`skipped`). Экспорт возможен только после итога «совпало» или «расхождение». Проект собирается и проходит `mvn test` без этого инструмента.

`GET …/export/junit/preview?jobId=…` — то же без файла, для окна экспорта. Настоящий ответ (вс 25.10):
```json
{ "zipName": "MatchDemo-tests.zip", "testFile": "src/test/java/MatchDemoCharacterizationTest.java",
  "framework": "JUnit Jupiter 6.1.3", "tests": 41, "skipped": 0, "firstTest": "…текст первого теста…" }
```
Ошибки: `404` — нет проекта; `400` — нет `jobId`; `409` — проверка не найдена, ещё идёт или её нельзя экспортировать.

## POST `/api/projects/{id}/heat` — частота посещений узлов

Запрос: `{ "methodId": "…id метода с карты…", "input": "текст stdin" }`.
`input` необязателен: отсутствие или `null` использует входы `InputGenerator`; явная пустая строка означает один прогон с пустым stdin.

Ответ содержит только результаты фактического выполнения копии со счётчиками:

| Поле | Значение |
|---|---|
| `methodId` | Измеренный метод |
| `runs` | Число выполненных прогонов |
| `counts` | Объект `id узла чертежа → суммарное число посещений оператора` |
| `maxCount` | Максимум среди значений `counts`, либо 0 при отсутствии посещений |
| `note` | Пояснение по-русски: что считалось, какие входы использованы и какие ограничения обнаружены |

Счётчик вставляется **перед оператором**, а связь с id берётся из `Blueprint.astById`. Номера строк используются только для точечных вставок текста, не для сопоставления узлов. Для цикла считается число входов в оператор цикла; это не число итераций его тела и не число проверок заголовка. Условие `if` считается при входе в оператор `if`.

Неизмеримые узлы отсутствуют в `counts`: их нельзя изображать как нули. К ним относятся неподдержанные raw-блоки и явные вызовы `this(...)` / `super(...)`, перед которыми существующий механизм не вставляет счётчик. Невызванный метод с измеримыми операторами возвращает реальные нули. Прогоны, завершившиеся исключением или ненулевым кодом выхода, учитываются при наличии полных счётчиков; `note` сообщает их число, а счётчики отражают посещения до завершения.

Ответы ошибок имеют обычную форму `{ "error": "пояснение по-русски" }`:

- `400` — неверный JSON, отсутствующий methodId или неверный тип input;
- `404` — проект или метод не найден;
- `422` — код не разбирается/не компилируется, нет запускаемого main, программа наблюдает стек (`StackSensitive`), не удалось собрать копию, таймаут, обрезанный/потерянный вывод, неполные или переполненные счётчики.

При недостоверном прогоне успешная частичная карта не возвращается; оставшиеся прогоны отменяются. Исходный проект не меняется. Замер не является проверкой эквивалентности поведения.

Интерфейс запрашивает карту только для открытого метода, показывает загрузку и текст серверной ошибки. Подписи и окраска появляются только для id из `counts`; после правки или смены метода результат сбрасывается, устаревшие ответы не применяются.

## Вложенные блоки выражений и дополнительные объявления

`GraphNode.branches` может быть задано и у обычного оператора (`stmt`, `return`, `throw`): так раскрываются тела лямбд с `{ … }` и блоки ветвей switch-выражений. Внешний узел сохраняет прежние `kind` и `id`. Вложенные операторы имеют `parent` этого узла и соответствующий ключ `branch`; они доступны через обычный `editStatement`. Оператор `yield` передаётся как редактируемый `stmt`, а его значение — в `expr`.

Ключи вложенных ветвей начинаются с `lambda:` или `switch:`. Они строятся по заголовку конструкции; повторяющиеся заголовки различаются суффиксом. Ветви switch дополнительно содержат `:case:<индекс>`. Рёбра `exec` соединяют соседние операторы внутри одной ветви; наличие тела лямбды на схеме не означает его вызова при создании лямбды.

Компактный конструктор record отображается как метод `#<init>` с типами компонентов record, например `M:Scope5Bonus.Pair#<init>(String,int)`. Константа enum с телом получает отдельного владельца: `C:Scope5Bonus.Op.<constant:ADD>`, а её метод — `M:Scope5Bonus.Op.<constant:ADD>#apply(int,int)`. Сегмент `<constant:…>` отделяет константы от настоящих вложенных типов; прежние идентификаторы методов сохраняются. Новые объявления доступны для построения чертежа, правки и замера частоты теми же маршрутами.
