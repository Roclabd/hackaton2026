## Кто что делает (файлы не пересекаются)
| Кто | Пакеты / папки | Маршруты |
|---|---|---|
| Главный агент | `graph/` (`MethodBlueprintBuilder`), `commands/`, `api/` (подключение всех маршрутов), `examples` | `GET /methods/{methodId}`, `POST /commands`, `GET /api/examples…` |
| Агент «Прогоны» | `runner/` (кроме `InMemoryCompiler`, `MemoryClassLoader`, `CompileResult` — их не менять), `inputs/`, `oracle/`, `gate/` | `POST /run`, `POST /gate`, `GET /api/jobs/{jobId}` — в классе `gate/GateRoutes` |
| Агент «Находки» | `diag/` | `GET /findings` — в классе `diag/FindingRoutes` |
| Агент «Фронт» | `frontend/` | — |

Маршруты агенты регистрируют статическим методом `register(JavalinConfig config, ProjectStore store)` в своём классе. В `ApiRoutes` их подключает главный агент.

## Ответы API (все пути с префиксом `/api/projects/{id}`)

### Чертёж метода — `GET /methods/{methodId}` (methodId — `encodeURIComponent`)
```json
{ "methodId": "M:MatchDemo#countMatches(List<Integer>,List<Integer>)",
  "label": "static long countMatches(List<Integer>, List<Integer>)",
  "nodes": [ GraphNode… ], "edges": [ { "kind": "exec", … } ] }
```
- `GraphNode` = как в API.md плюс `editable` (bool) и `branches` (`[{ "key": "then", "label": "да" }]` — только у контейнеров, иначе null).
- Операторы верхнего уровня: `parent` = methodId, `branch` = `"body"`.
- Контейнеры: `if` (ветки `then` «да» / `else` «нет»), `loop` (`body`), `switch` (`case:N` с подписью `case 1:` / `default:`), `try` (`body`, `catch:N`, `finally`).
- `code` у `stmt`, `return`, `throw` — оператор целиком. У `if`, `while`, `do` — условие: ровно то, что подставится в поле правки.
- `editable`: оператор — да; `if`, `while`, `do` — да (правится условие); `for`, `foreach`, `switch`, `try`, `raw` — нет.

### Правка узла — `POST /commands`
Запрос: `{ "type": "editStatement", "nodeId": "…", "text": "x.equals(y)", "baseVersion": 1 }`
Ответ `200`: `{ "ok": true, "version": 2, "source": "…", "errors": [], "map": Graph, "idMap": { "старый": "новый" }, "methodId": "…", "blueprint": Blueprint, "compileErrors": [] }`
Не компилируется или не разбирается — `200` с `{ "ok": false, "compileErrors": [{ "line": 16, "column": 21, "text": "…" }] }`, версия не меняется. Устаревшая версия — `409`.

### Прогон — `POST /run`
Запрос `{ "input": "1 2\n2 3" }` → `RunResult`:
```json
{ "stdout": "Совпадений: 1\n", "stderr": "", "exitCode": 0,
  "exception": null, "timedOut": false, "durationMs": 21 }
```
`exception`: `{ "type": "java.lang.NullPointerException", "message": "…" }` или `null`.

### Проверка — `POST /gate` → `GET /api/jobs/{jobId}`
Запрос: `{ "source": "…полный текст кандидата…", "intent": "REFACTOR" | "BUGFIX" }` → `{ "jobId": "j1" }`. Оригинал — текущая версия проекта на момент запроса.
Опрос `GET /api/jobs/{jobId}` раз в 300 мс:
```json
{ "status": "RUNNING | MATCHED | MISMATCH | INCOMPLETE | BUILD_ERROR | BEHAVIOR_CHANGE",
  "phase": "compile | run | compare | done", "progress": 0.0,
  "inputs": 30, "checked": 30, "mismatches": 0, "nondeterministic": 0,
  "incompleteReason": null,
  "buildErrors": [{ "line": 16, "column": 21, "text": "…" }],
  "smallestMismatch": { "input": "null\n1", "group": "Значения null",
                        "original": RunResult, "candidate": RunResult },
  "example": { "input": "1 1 3\n1 2", "group": "Обычные значения", "original": RunResult, "candidate": RunResult },
  "groups": [{ "name": "Значения null", "total": 6, "checked": 6, "matched": 5, "status": "MISMATCH" }],
  "changedCovered": null, "speedup": null, "durationMs": 1400 }
```
`example` — пара прогонов для показа при `MATCHED` (самый короткий вход). Статус `RUNNING` — пока `progress < 1`.

### Находки — `GET /findings`
```json
[{ "id": "R1-1", "rule": "R1", "methodId": "M:MatchDemo#countMatches(List<Integer>,List<Integer>)",
   "lines": [14, 20], "title": "Вложенный цикл",
   "why": "Для каждого элемента a просматривается весь список b: число сравнений растёт как n².",
   "category": "INEFFICIENCY", "growthBefore": "n²", "growthAfter": "n",
   "conditions": ["…"],
   "patches": [{ "id": "R1-1-index", "intent": "REFACTOR", "title": "Индекс частот вместо перебора",
                 "description": "…", "source": "…полный текст файла с заплаткой…", "changedLines": [14, 22] }] }]
```

Поле `category`: `INEFFICIENCY` / `DEFECT` / `DEAD_CODE`. У находок без оценки сложности оба поля роста — `null`.

| Правило | Что проверяет | Категория и намерение заплатки |
|---|---|---|
| R1 | Вложенный перебор с равенством ключей | `INEFFICIENCY`; эквивалентная заплатка `REFACTOR` |
| R2 | Простой индексный обход `0 … <= array.length` с обращением к элементу | Потенциальный `DEFECT`, `BUGFIX` |
| R3 | Недостижимая группа private-методов простого класса | `DEAD_CODE`, `REFACTOR`; динамический результат может быть `INCOMPLETE` |
| R4 | Обратное сравнение в явно названном поиске max/min | Потенциальный `DEFECT`, `BUGFIX` |
| R5 | Деление на `length - 1` в вычислении среднего | Потенциальный `DEFECT`, `BUGFIX` |
| R6 | Присваивание вместо сравнения в условии | `DEFECT`, `BUGFIX`; намеренность присваивания нужно проверить |
| R7 | Сравнение двух известных строк через `==` | Потенциальный `DEFECT`, `BUGFIX`; интернирование может быть намеренным |
| R8 | Целочисленное деление перед преобразованием в `double` | Потенциальный `DEFECT`, `BUGFIX`; усечение может быть намеренным |
| R9 | Склейка строки в цикле (`s += x`, `s = s + x`) | `INEFFICIENCY`, `REFACTOR`: StringBuilder перед циклом, `append` внутри, `toString()` после. Только если внутри цикла s лишь дописывается. `growthBefore/After = null`: n² — это скопированные символы, а не шаги цикла |

Точные ограничения и расширенный формат `changedCovered` описаны в [API.md](API.md). Ошибка замера реальной правки не разрешает `MATCHED`; счётчики не используются как эталон поведения.

## Java-сигнатуры (для агентов бэкенда)
- `blueprints.project.ProjectStore`: `find(id)`, `create(fileName, source)`, `updateSource(id, expectedVersion, source)`. `Project`: `id()`, `version()`, `source()`, `fileName()`, `lastGood()` (`Optional<CompilationUnit>`).
- `blueprints.runner.InMemoryCompiler#compile(mainClassName, source)` → `CompileResult(ok, classes, messages)`.
- Агент «Прогоны» создаёт: `runner.RunResult`, `runner.MainClassFinder#find(CompilationUnit)`, `runner.ProgramRunner` (рабочий процесс JVM), `inputs.InputGenerator`, `oracle.Oracle`, `gate.GateService`, `gate.Verdict`, `gate.GateRoutes`.
- Агент «Находки» создаёт: `diag.FindingsService`, `diag.Finding`, `diag.Patch`, `diag.FindingRoutes`.
